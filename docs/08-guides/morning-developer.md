## 1. Что происходит без вашего участия

1. `partner-agent` открывает сессию с задачей и веткой
   (`POST /v1/sessions`).
2. Каждые 30 секунд уходит heartbeat с интервалом, классом времени и
   счетчиками сигналов (`input_events`, `focus`, `tool_calls`).
3. Ночью сервер закрывает день в 00:00 пояса проекта; после закрытия
   формируется дайджест и ставится в очередь доставки.
4. Деньги и доля считаются только сервером по `policy.yaml`; агент
   ничего не начисляет.

Ваши обязанности: держать сессию привязанной к задаче/ветке и не
подменять сигналы активности. Работа без задачи (`task_ref`) попадает в
учет как `idle` и не оплачивается.

## 2. Утро: читаем дайджест

Дайджест приходит в настроенный канал (`agent_chat`, почта или webhook) и
доступен через API. Пример закрытого дня по сценарию T-01:

```text
Дайджест дня 2026-11-12 — dev1 (проект partner, Europe/Moscow)
Оплачиваемое время: 6.6 ч
  человек (active_human): 4 ч
  агент под наблюдением (supervised_agent): 2.0 ч
  автономный агент (autonomous_agent): 0.6 ч
Начислено: 3300 ₽ (cash 0 ₽ / доли 3300 ₽)
Доля дня: 0.0330 % (3.3000 бп)
Версии: ставка r1, политика v1; sha256 4f1c2a9d8e77…
```

Проверка чисел:

| Шаг | Расчет | Итог |
|---|---|---|
| Активное время | 4 ч × 500 ₽ | 2 000 ₽ |
| Супервизия | 2 ч × 1,0 × 500 ₽ | 1 000 ₽ |
| Автономный агент | 3 ч × 0,2 = 0,6 оплач. ч × 500 ₽ | 300 ₽ |
| Простой | 1 ч × 0 | 0 ₽ |
| Итого | 6,6 оплач. ч × 500 ₽ | **3 300 ₽** |
| Доля дня | 3 300 / 10 000 000 × 100 | **0,0330%** |

Кап автономного времени — 2,0 оплач. ч; здесь 0,6 ч, поэтому флага
`autonomous_cap_applied` нет. Дневной кап — 12 ч; здесь 6,6 ч.

## 3. Как получить те же числа

Через API сервера (подставьте свой проект, участника и токен):

```bash
curl -sS "https://partner.example/v1/digest/day/2026-11-12?participant_id=dev1&project_id=partner" \
  -H "Authorization: Bearer $PARTNER_API_TOKEN"
```

В ответе `text` — тот же текст, что ушел в уведомление, а поля
`paid_hours`, `amount_rub`, `share_pct`, `flags` — для проверок.

Раскладка по интервалам, классам и капам:

```bash
curl -sS "https://partner.example/v1/days/2026-11-12/explain?participant_id=dev1&project_id=partner" \
  -H "Authorization: Bearer $PARTNER_API_TOKEN"
```

Если сервер использует один проект, те же данные доступны CLI:

```bash
export PARTNER_SERVER_URL=https://partner.example
export PARTNER_API_TOKEN=...
partner digest day 2026-11-12 --participant dev1
```

Локальная демонстрация без сервера (`partner day --demo`) считает тот же
T-01 и печатает 6,6 ч / 3 300 ₽ / 0,0330%.

## 4. Если цифры не сходятся

1. **Сначала `explain`.** Проверьте `raw_pieces`: не потерялся ли
   интервал, не попал ли он в соседний день из-за полуночи (T-05) и какой
   класс присвоен.
2. **Проверьте привязку.** `no_task_link` означает сессию без задачи:
   время учтено, но не оплачено. Исправляется только новой сессией с
   `task_ref`; прошлые интервалы задним числом не переписываются.
3. **Проверьте флаги.** `idle_no_signal` — супервизия без сигналов ввода;
   `synthetic_input` — подозрение на макросы; `clock_skew` — часы
   источника убежали вперед; `no_output` — оплачено больше 3 ч без
   коммитов/PR и `tool_calls`.
4. **Поздние данные.** События в пределах грейса сервера
   (`PARTNER_GRACE_HOURS`, по умолчанию 24 ч) принимаются, и закрытый
   день получает компенсирующую корректировку; события за грейсом
   отклоняются (`late_rejected`) и не оплачиваются.
5. **Спор.** Если расхождение не объясняется, откройте спор по закрытому
   дню в окне 3 суток:

```bash
curl -sS -X POST "https://partner.example/v1/days/2026-11-12/disputes?project_id=partner" \
  -H "Authorization: Bearer $PARTNER_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"participant_id":"dev1","opened_by":"dev1","reason":"нет интервала 14:00–15:00","interval_ids":["evt-..."]}'
```

В ответе будет `dispute_id` и `window_deadline`. Решение принимает
директор: `approved` создает `adjustment`, `rejected` оставляет день как
есть. День не перезаписывается — меняется только эффективная сумма.

## 5. Офлайн и часовые пояса

- При потере сети события копятся в `agent-buffer.jsonl` и уходят в
  порядке `seq` после восстановления связи.
- Буфер не спасает от грейса: если событие пришло позже
  `PARTNER_GRACE_HOURS`, оно получит `late_rejected`.
- Интервал, пересекающий локальную полночь, делится на два дня (T-05):
  22:00–02:00 даст 2 ч в день D и 2 ч в день D+1.
- Часы считаются в поясе проекта (`projects.timezone`), а не в поясе
  вашей машины.

## 6. Чек-лист дня

- [ ] Сессия начата с `task_ref` и веткой `dev/<логин>/<тема>`.
- [ ] `partner-agent run` или IDE-плагин отправляет heartbeat.
- [ ] Утром прочитан дайджест; числа совпали с `explain`.
- [ ] Флаги понятны; при `no_output` есть коммит/PR или `tool_calls`.
- [ ] При расхождении спор открыт до дедлайна (3 суток).
- [ ] Офлайн-буфер отправлен (`partner-agent flush`), если был простой сети.
