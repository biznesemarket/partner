# Юридический модуль (опциональный)

| Поле | Значение |
|---|---|
| Версия | 1.0 |
| Дата | 2026-11-13 |
| Переносит | C-трек прежней версии (C1–C13) как опциональный модуль |
| Связанные | equity-model §7, ADR-0019, vision («юридическое — опция») |

## 1. Принцип: продукт работает без юридического блока

Пока `legal.enabled: false`, система ведет учет вклада: копит рубли
вклада и показывает расчетную долю. Она не создает юридических обещаний
и не оформляет долю. Это позволяет продавать продукт организациям с любой
юрисдикцией и на любом этапе зрелости.

Включение модуля — отдельный сценарий: юрист снимает гейты (§4),
заполняются опциональные поля политики, `legal.enabled: true`.

## 2. Основная юридическая модель: фантомные доли (динамический пул)

Рекомендуемая и задокументированная как основная модель — **фантомные
доли (phantom shares) через динамический пул**, адаптация идеи Slicing Pie
под российскую практику:

1. Вклад участника измеряется в рублях вклада (время × ставка, версиям
   ставки — versioning.md) и в денежных вкладах партнеров.
2. Пул = `pool_pct` от оценки проекта (дефолт 30%); пол основателя —
   `founder_floor_pct` (дефолт 70%).
3. Расчетная доля каждого = его вклад-рубли / оценка. Доля пересчитывается
   при переоценке прозрачно для всех.
4. **Фиксация — по месячным снапшотам**: раз в месяц (или по решению
   директора) итоги закрепляются git-якорем с SHA-256 и, после создания
   юрлица, оформляются сделками: договор участников, корпоративный договор,
   опционные соглашения.
5. До фиксации фантомная доля — «доля-баллы», обязательство оформить
   которое берет на себя организация в договоре с участником.

Почему не прямые доли в ООО сразу: выпуск доли требует нотариуса,
изменения УК и налоговых решений на каждом начислении — это ломает
ежедневную модель. Фантомная доля накапливается тихо и конвертируется
в реальную юрлицом-событием (создание ООО, раунд, выход).

## 4. Гейты (все должны быть сняты юристом до legal.enabled: true)

| Гейт | Предмет | Приоритет |
|---|---|---|
| G-01 | Денежная часть вознаграждения (cash_share_pct) | P0 |
| G-02 | Конструкция обещания доли (фантомная доля в договоре) | P0 |
| G-03 | Публичные формулировки продукта и сайта | P1 |
| G-04 | Хранение и защита данных | P0 |
| G-05 | Договорная база участника (договор + CLA + NDA) | P0 |
| G-06 | Налоги (НДФЛ, взносы, УСН-ограничения) | P0 |
| G-07 | Персональные данные и трансграничная передача | P0 |
| G-08 | Пакет фиксации (создание нового ООО по снапшоту) | P2 |

## 5. Красные линии (действуют при любом статусе модуля)

- Не обещать «долю в ООО» в текстах продукта до фиксации — только
  «расчетную долю / долю-баллы».
- Не публиковать персональные данные и цифры участников.
- Не вести юридические обещания в коде: только в договорах.
- Налоговые последствия начислений — консультация юриста; система
  экспортирует данные, но не решает налоги.

## 6. IP-политика (выжимка)

- Исключительные права на результаты работ оформляются договором
  с участником (ст. 1296 ГК РФ: результат по договору заказчику, но
  требуются явные формулировки отчуждения).
- CLA/соглашение об отчуждении подписывается до первого принятого вклада.
- Данные для сборки договоров — в закрытом контуре, не в git клиента.

## 7. Экспорт юристу

```text
partner export-legal --to lawyer/
```

Собирает: текущую политику (без персональных данных), месячные снапшоты,
список гейтов, вопросы юристу. Пакет предназначен для отправки юристу;
полные тексты договоров (I7) подключаются как шаблоны.

Реализация (M7): пакет собирает сервер `POST /v1/legal/export` и
раскладывает CLI в каталог (`policy.json/md`, `snapshots/<месяц>.md`,
`snapshots.json`, `gates.md`, `questions-to-lawyer.md`, `templates/*.md`,
`MANIFEST.txt` с подписываемым `bundle_sha256`). Шаблоны фиксации
(договор участников / опцион / заём / чек-лист создания ООО) — редакционные,
без логики (§4 плана разработки M7.4).

Снапшоты (M7.1): `partner snapshot-close <YYYY-MM>` — иммутабельный
месячный итог (вклад ₽, расчетные доли, версии политики) с sha256 по
canonical JSON и git-якорем; повтор с тем же содержимым — duplicate,
с другим — конфликт (снапшот не переписывается).

Гейты (M7.3): `partner legal-gates` — отчет; `partner legal-gate G-xx
--status done --evidence "…" --by юрист`; `partner legal-enable` —
включение запрещено, пока не сняты все гейты (отказ с перечнем). Состояние
— файл `legal.yaml` (переменная `PARTNER_LEGAL_FILE`; образец —
`legal.state.example.yaml` в этом каталоге).

## 8. Что не делаем

- Не автоматизируем подписание и нотариат.
- Не храним договоры в репозитории проекта.
- Не начисляем «юридическую долю» без включенного модуля и снятых гейтов.
