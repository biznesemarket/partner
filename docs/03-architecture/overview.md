## 1. Архитектурные принципы

1. **Гибридное хранилище (ADR-0016).** Поток событий времени → БД
   (истина для событий); принятые дневные итоги и месячные снапшоты →
   якорь в git (доказательная база для споров и юриста).
2. **Self-hosted, мультитенантность.** Организация → проекты → участники;
   данные клиента не покидают его периметр.
3. **Правила в репозитории клиента.** policy.yaml + AGENTS.md — источник
   правил; сервер читает и версионирует.
4. **Deny by default.** Все телеметрия и API — по подписанным токенам
   со скоупами (наследие ADR-0007).
5. **Минимум сервисов в MVP.** Витрина — дайджест + CLI (ADR-0018);
   дашборд не строим до спроса.

## 2. C4 L1 — контекст системы

| Актор | Взаимодействие |
|---|---|
| Директор | настраивает политику (wizard), получает сводки, корректирует дни |
| Разработчик | работает с агентом в ветке; получает дайджест и CLI-отчеты |
| ИИ-агент | работает в IDE/CLI; отправляет heartbeat через agent-kit |
| Git-платформа | GitHub / Forgejo: вебхуки событий веток и PR |
| Юрист (опция) | получает пакет: снапшоты, политика, вопросы (гейты) |

## 3. C4 L2 — контейнеры

| Контейнер | Технология | Ответственность |
|---|---|---|
| partner-server | Python, FastAPI | API, планировщик (закрытие дня, дайджест), правила |
| PostgreSQL | PostgreSQL 15+ | сессии, heartbeat, интервалы, дневные записи (истина) |
| partner-cli | Python, Typer | init, status, day, explain, snapshot; прототип на SQLite |
| partner-agent-kit | плагин IDE + MCP | сессии, heartbeat, буферизация offline, подпись |
| partner-connector-* | Python | вебхуки, ветки, PR, черновые записи |
| repo-pack | файлы | policy.yaml, AGENTS.block.md, workflows |

## 4. C4 L3 — ядро расчета (server)

```text
ingest (heartbeat API) → interval_builder → classifier (классы)
  → union/split (R3, R4) → caps (R5) → day_closer (00:00 пояса)
  → calculator (R1, R14) → day_records → anchor_writer (git)
  → digest_sender (09:00)
```

Планировщик выполняет две критические джобы: `day_close` в 00:00 пояса
проекта и `digest_send` в digest_hour. Джобы идемпотентны: повторный
запуск дня не создает дубликатов.

## 5. API (эскиз; полная OpenAPI-спецификация — итерация I4)

| Группа | Эндпоинты (эскиз) |
|---|---|
| События | POST /v1/heartbeats (батч, подпись), GET /v1/sessions/{id} |
| Дни | GET /v1/days/{date}, POST /v1/days/{date}/adjust, GET /v1/days/{date}/explain |
| Политика | GET /v1/policy, POST /v1/policy/versions |
| Отчеты | GET /v1/snapshot/{YYYY-MM}, GET /v1/digest/{participant} |
| Споры | POST /v1/disputes, GET /v1/disputes/{id} |

Формат ошибок: RFC 7807 problem+json с кодами X-xx/V-xx валидатора.

## 6. Коннекторы

| Платформа | Механика | Статус |
|---|---|---|
| GitHub | App/токен, вебхуки push/PR/issues, метки задач | реализовано v1.1: `connector_routes.py` |
| Forgejo / Gitea | токен, вебхуки, совместимость API | реализовано v1.1: те же маршруты и `repo_facts` |
| AGENTS.md-протокол | агент читает блок правил первым; правила учета времени обязательны | спецификация в repo-pack |

Контракт адаптера (наследие ADR-0006): выход адаптера — черновая запись
в БД, не прямое начисление; расчет — только rules engine.

## 7. Развертывание

MVP-поставка: Docker Compose (server + PostgreSQL + nginx) на VM клиента.
Подробная инструкция — docs/07-ops/installation.md; полный операционный
трек (бэкапы, мониторинг, runbook) — итерация I8.

## 8. Эволюция и риски

| Риск | Мера |
|---|---|
| Накрутка времени | классы времени, капы, флаги (time-accounting §9), красные тесты I5 |
| Потеря БД | бэкапы + git-якоря итогов; пересмотр ADR-0013 в I8 |
| Смена платформы | коннекторный контракт, метки как единственный машиночитаемый контракт |
| Спор о расчете | explain-раскладка + SHA-256 снапшотов |
