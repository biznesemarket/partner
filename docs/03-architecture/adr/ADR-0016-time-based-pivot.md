# ADR-0016: Пивот — учет времени с ИИ вместо цены задачи; продукт на продажу

| Поле | Значение |
|---|---|
| Статус | Принято |
| Дата | 2026-11-13 |
| Решающий | Основатель |
| Заменяет | ADR-0004 (частично), ADR-0006 (частично), ADR-0011 (частично) |
| Связанные | 02-policy/time-accounting, ADR-0017, ADR-0018 |

## Контекст

Прежняя модель требовала от директора объявлять цену каждой задачи до старта.
На практике директор не знает стоимость разработки, а работа ведется через
ИИ-агентов и идет быстрее ручной. Кроме того, продукт решено продавать
другим организациям, а не строить только под ООО «ФОНИИ».

## Решение

1. **Основной режим учета — время работы с ИИ-агентом × ставка часа.**
   Ставка (дефолт 500 ₽/ч) — переменная политики, задаётся при настройке
   и изменяется директором с даты вступления в силу.
2. **Режим цены задачи сохраняется как опциональный** (`fixed_price`)
   для организаций, которые умеют оценивать работы. Гибрид разрешён.
3. **Продукт универсален и мультитенантен**: организация → проекты → участники.
   ООО «ФОНИИ» — первый клиент (tenant #1), а не владелец правил.
4. **Начисление ежедневное.** День закрывается автоматически (ADR-0017).
5. **Юридический блок опционален**: система работает как учет вклада;
   оформление долей включается отдельным модулем позже.
6. **Хранилище — гибрид.** Поток событий времени → PostgreSQL (истина
   для событий). Принятые дневные итоги и месячные снапшоты → фиксация
   в git (доказательная база). Прежний принцип «git — истина для всего»
   заменен: события слишком часты для git.
7. **Политика проекта хранится в репозитории клиента** (`policy.yaml`)
   и в блоке AGENTS.md; сервер читает и версионирует её.

## Что сохраняется из прежнего

Модель долей, пул, вестинг, идентификация «человек ↔ аккаунты», запрет
заднего числа, компенсирующие записи, окно спора, роли и RBAC, модель
угроз, эксплуатационный трек, юридический трек — всё переносится
(карта: docs/00-start/migration-map.md).

## Альтернативы

Оставить цену задачи основной — отклонено (директор не может оценивать).
Считать «сырое» время агента без разделения — отклонено (накрутка ночными
прогонами). Строить только под ФОНИИ — отклонено (упущен рынок).

## Последствия

Плюсы: директору не нужно оценивать работы; продукт продаваем; ежедневная
обратная связь мотивирует.
Минусы: появляется класс рисков «накрутка времени» — закрывается моделью
учета (02-policy/time-accounting) и антифродом; требуется агент-кит
и сервер, а не только файлы в git.
