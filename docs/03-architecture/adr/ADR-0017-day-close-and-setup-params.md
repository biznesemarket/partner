# ADR-0017: Закрытие дня в 00:00 MSK; кап и коэффициент задаёт директор

| Поле | Значение |
|---|---|
| Статус | Принято |

| Решающий | Основатель |
| Связанные | 02-policy/time-accounting, 00-start/quickstart, onboarding-wizard |

## Контекст

Начисление ежедневное, значит нужна точная граница суток и понятные
директору параметры антифрода, которые он задает сам при настройке.

## Решение

1. **Закрытие дня — автоматически в 00:00 по Москве (Europe/Moscow, UTC+3).**
   Граница суток фиксирована; перехода на летнее время в РФ нет.
   Для tenant #1 (ФОНИИ) часовой пояс фиксирован MSK.
   Для других организаций часовой пояс — переменная политики
   (`timezone`, дефолт `Europe/Moscow`); день закрывается в 00:00
   настроенного пояса. Все события хранятся в UTC.
2. **Коэффициент автономного времени агента — обязательный вопрос
   при настройке.** Диапазон 0–1, рекомендация 0,2–0,3, дефолт 0,2.
3. **Дневной кап часов — обязательный вопрос при настройке.**
   Рекомендация 10 или 12, дефолт 12. Применяется к оплачиваемым часам.
4. **Дополнительный кап на автономный класс** — `autonomous_paid_cap_hours`,
   дефолт 2,0 оплачиваемых часа в сутки; задаётся при настройке.
5. **Подтверждение дня не требуется.** День закрывается сам; директор
   корректирует в окне оспаривания (`day_dispute_window_days`, дефолт 3).
6. **Дайджест утром** в час, заданный при настройке (дефолт 09:00 пояса проекта).

## Альтернативы

Явное подтверждение каждого дня директором — отклонено (не масштабируется
при ежедневном начислении). Закрытие в 23:59 локального времени сервера —
отклонено (неоднозначно при разных поясах).

## Последствия

Директор не выполняет рутинных подтверждений, но сохраняет контроль
через окно корректировки и флаги аномалий. Ночные автономные прогоны
не превращаются в полную оплату благодаря коэффициенту и отдельному капу.
