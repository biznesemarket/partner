# Мастер настройки (`partner init`) и repo-pack

| Поле | Значение |
|---|---|
| Код | ARCH-ONBOARDING |
| Версия | 1.0 (итерация I3) |
| Дата | 2026-11-13 |
| Связанные | policy-schema (x-wizard), repo-pack/, quickstart, ADR-0016, ADR-0017 |

Цель: установка «Партнера» в чужой репозиторий проходит **без программиста** —
директор или юрист отвечает на вопросы, мастер пишет policy.yaml, блок
AGENTS.md и делает коммит версии 1.0.

## 1. Источник вопросов

Вопросы генерируются из `x-wizard`-разметки схемы политики
(policy-schema.md §1): поле помечено `ask: mandatory | optional`,
текстом вопроса, диапазоном и подсказкой. Мастер и схема не могут
разойтись: нет ручного списка вопросов.

## 3. Обязательные вопросы (без них система не стартует)

| # | Вопрос | Валидация | Дефолт |
|---|---|---|---|
| 1 | Название организации | непустое | — |
| 2 | Название проекта | непустое | — |
| 3 | Валюта | enum RUB/USD/EUR | RUB |
| 4 | Оценка проекта | целое > 0 | — |
| 5 | Ставка часа | целое > 0 | 500 |
| 6 | Часовой пояс | валидный IANA tz | Europe/Moscow |
| 7 | Дневной кап | число 4–16 | 12 |
| 8 | Коэффициент автономного времени | число 0–1 | 0,2 |
| 9 | Пул участников | число 1–99, pool + founder_floor ≤ 100 | 30 |
| 10 | Утверждающий дни | имя/логин | — |

## 4. Опциональные вопросы (можно пропустить)

Реквизиты юрлица, юрисдикция, параметры вестинга, тип договора,
налоговые настройки, согласия на обработку данных, целевой срок создания
юрлица, политика автономного времени агента. Пропущенные поля пишутся
`null` и помечаются в предпросмотре как «заполнить позже».

## 5. Что делает мастер (спецификация `partner init`)

| Шаг | Действие | Проверка |
|---|---|---|
| 1 | Читает x-wizard-схему, ведет диалог | обязательные поля заполнены |
| 2 | Собирает policy.yaml (дефолты для неспрошенных) | policy_lint OK |
| 3 | Показывает предпросмотр и список файлов | подтверждение директора |
| 4 | Пишет policy.yaml; добавляет блок в AGENTS.md (создает файл, если нет) | блок идемпотентен (маркеры BEGIN/END) |
| 5 | Копирует workflows из repo-pack | .github/workflows/partner-policy-check.yml |
| 6 | Коммит «policy v1.0» с SHA-256 политики | чистое рабочее дерево |
| 7 | Печатает краткую инструкцию участникам | — |

Флаги: `--demo` (обезличенные демо-ответы для теста), `--non-interactive file.yaml`
(импорт из файла ответов), `--dry-run` (только предпросмотр).

## 6. Смена параметров директором

- Ставка, оценка, кап, коэффициент — через новую версию в `versions[]`
  (`partner policy set rate 600 --reason "…"`) — см. versioning.md.
- Юридические поля — после гейтов юриста: `partner policy legal-enable`.
- Задним числом менять нельзя; валидатор V-04 блокирует.

## 7. Repo-pack: состав пакета

| Файл | Назначение |
|---|---|
| repo-pack/AGENTS.block.md | Блок правил, вставляемый в AGENTS.md репозитория клиента |
| repo-pack/policy.example.yaml | Стартовая политика-образец |
| repo-pack/workflows/partner-policy-check.yml | CI: валидация policy.yaml при каждом PR |
| repo-pack/README.md | Инструкция установки пакета |

## 8. Критерии приемки I3

- [x] Мастер генерирует политику из схемы, без ручного списка вопросов.
- [x] Скелет `partner init --demo` создает валидную политику
      (проверяется policy_lint) и блок AGENTS.md.
- [x] Пропуск опциональных вопросов не блокирует запуск.
- [x] По quickstart.md установка проходит без программиста.
- [ ] Реализация на серверной стороне (телеметрия, планировщик) — I4.
