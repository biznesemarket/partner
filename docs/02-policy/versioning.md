# Версионирование ставки и оценки

| Поле | Значение |
|---|---|
| Код | POLICY-VERSIONING |
| Версия | 1.0 |
| Дата | 2026-11-13 |
| Связанные | policy-schema §8, §14, time-accounting §8, ADR-0016 |

## 1. Зачем

Директор меняет ставку и оценку по ходу проекта. Без версий любое изменение
либо обесценит прошлый труд, либо создаст спор. Версии делают расчет
воспроизводимым: спустя год можно повторить любой день.

## 2. Формат записи

```yaml
versions:
  rate:
    - effective_from: "2026-11-13T00:00:00+03:00"
      value: 500
      reason: "Стартовая ставка"
      approved_by: founder
    - effective_from: "2027-01-01T00:00:00+03:00"
      value: 600
      reason: "Рост квалификации команды"
      approved_by: founder
  valuation:
    - effective_from: "2026-11-13T00:00:00+03:00"
      value: 10000000
      reason: "Стартовая оценка"
      approved_by: founder
      adr_ref: ADR-0016
```

## 3. Правила применения

1. Для интервала времени действует последняя запись с
   `effective_from ≤ начало интервала`.
2. Если ставка меняется внутри дня — день делится на отрезки,
   каждый считается по своей ставке.
3. Для доли дня действует оценка, активная на момент закрытия дня.
4. Каждая дневная запись хранит `rate_version`, `valuation_version`,
   `policy_version`.

Пример: ставка 500 до 14:00, затем 600; active 09:00–15:00 →
5 ч × 500 + 1 ч × 600 = 3 100 ₽.

## 4. Правила изменения

| Правило | Значение |
|---|---|
| Новая запись | только с `effective_from` ≥ начала текущего открытого дня |
| Прошедшие записи | неизменяемы и неудаляемы |
| Оценка | требует `adr_ref` и уведомления за `revaluation_notice_days` |
| Ставка | требует `reason` и `approved_by` |
| Порядок | `effective_from` строго возрастает |
| Пересчет прошлых дней | запрещен |

## 5. Ошибка в ставке: что делать

Если ставка была задана неверно (например 5000 вместо 500) и дни уже закрыты:

1. **Нельзя** датировать новую версию прошлым числом.
2. Добавить корректную версию с текущей даты.
3. Закрытые дни исправить **компенсирующими записями** с обоснованием
   и ссылкой на ADR/решение директора.
4. Уведомить участников: что изменилось, за какие дни, на сколько.

Валидатор блокирует попытку задним числом (проверка V-04).

## 6. Проверки валидатора

| ID | Проверка |
|---|---|
| V-01 | в каждом массиве ≥ 1 запись |
| V-02 | effective_from строго возрастает |
| V-03 | value > 0 |
| V-04 | новая запись не раньше начала текущего открытого дня |
| V-05 | у оценки есть adr_ref |
| V-06 | reason ≥ 5 символов, approved_by заполнен |
| V-07 | текущая ставка в economics совпадает с последней активной версией |
| V-08 | текущая оценка в economics совпадает с последней активной версией |

V-07/V-08 защищают от рассинхрона «витрина политики ↔ история версий».

## 7. Отображение в дайджесте

При смене ставки или оценки участник получает отдельное уведомление:
«С 01.01.2027 ставка 600 ₽/ч. Прошлые начисления не меняются».
При переоценке дополнительно: «Ваша доля изменится с 1,0% до 0,5%,
накопленные рубли неизменны».
