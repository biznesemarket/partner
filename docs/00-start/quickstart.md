## Роль 1. Директор — настройка за 15 минут

Директор запускает мастер настройки один раз. Программист не нужен.

### Шаг 1. Установить CLI в репозиторий проекта

```bash
# в корне репозитория проекта клиента
# поставка: приватный индекс или wheel-артефакт релиза (см. installation.md §3)
pip install --index-url <PRIVATE_INDEX> partner-tracker
partner init
```

Для локальной разработки самого продукта: `pip install -e .`.

### Шаг 2. Ответить на вопросы мастера

Мастер задает 10 обязательных вопросов (без них система не стартует):

| # | Вопрос | Дефолт / пример |
|---|---|---|
| 1 | Название организации | ООО «ФОНИИ» |
| 2 | Название проекта и ветка по умолчанию | «Партнер», main |
| 3 | Валюта | RUB |
| 4 | Оценка проекта (100%) | 10 000 000 ₽ |
| 5 | Ставка часа работы с ИИ-агентом | 500 ₽/ч |
| 6 | Часовой пояс закрытия дня | Europe/Moscow |
| 7 | Дневной кап оплачиваемых часов | 12 |
| 8 | Коэффициент автономного времени агента | 0,2 (реком. 0,2–0,3) |
| 9 | Пул участников, % от оценки | 30% |
| 10 | Кто утверждает дни и корректировки | директор |

Опциональные вопросы (можно пропустить и заполнить позже): реквизиты
юрлица, юрисдикция, параметры вестинга, тип договора, налоговые настройки,
согласия на обработку данных, целевой срок создания юрлица, политика
автономного времени агента.

### Шаг 3. Проверить предпросмотр и зафиксировать

Мастер показывает предпросмотр `policy.yaml`, пишет его в корень репозитория,
добавляет блок правил в `AGENTS.md` (если файла нет — создает) и делает
коммит «policy v1.0». Валидация: `python tools/policy_lint.py policy.yaml`.

### Шаг 4. Создать ветки разработчиков

```bash
git checkout -b dev/ivanov/42
partner-agent init --participant ivanov --task 42 --branch dev/ivanov/42
partner-agent run          # heartbeat каждые 30 с; Ctrl+C — финальный интервал
```

Дальше учет идет автоматически: кит фиксирует сессию в ветке, коннектор
заполняет `task_ref` по ветке, в 00:00 по Москве день закрывается, утром
приходит дайджест. Без `partner-agent` время в сервер не попадает.

## Роль 2. Разработчик — работа и утренний дайджест

```bash
partner status               # текущая сессия, сегодня начислено
partner day                  # итог вчерашнего дня: часы по классам, ₽ и %
partner explain 2026-11-12   # раскладка: интервалы, классы, капы, флаги
partner snapshot 2026-10     # месячный итог и прогресс вестинга
```

Правила, о которых важно знать:

- активное время — 100% ставки; супервизия агента — `k_supervised`;
  автономная работа агента (человека нет) — `k_autonomous` (0,2) и не более
  2,0 оплачиваемых часов в сутки;
- параллельные сессии не суммируются (union);
- простой дольше 5 минут не оплачивается, сессия ставится на паузу;
- сессия без привязки к задаче/ветке учитывается, но не оплачивается;
- день закрывается сам; спор — в течение 3 суток через форму спора.

## Роль 3. Юрист — когда долю нужно закрепить

1. Запросить у директора пакет юристу: `partner export-legal --to lawyer/`
   (снапшоты, политика, список вопросов).
2. Открыть `docs/06-legal/legal-module.md`: основная модель — фантомные
   доли (динамический пул), юридическая фиксация — по месячным снапшотам.
3. Снять гейты G-01…G-08 (см. 06-legal) до включения `legal.enabled: true`.
4. Пока модуль выключен — система ведет учет вклада; доля расчетная,
   юридических обещаний система не создает.

## Проверка установки (все роли)

| Проверка | Команда | Ожидание |
|---|---|---|
| Политика валидна | `python tools/policy_lint.py policy.yaml` | `OK: политика валидна …` |
| Калькулятор корректен | `pytest` (в репозитории продукта) | 170 passed (T-01…T-12 + сервер) |
| Демо-день считается | `partner day --demo` | 6,6 ч → 3 300 ₽ → 0,0330% |
| Правила в AGENTS.md | открыть `AGENTS.md` | блок «Правила учета «Партнер»» на месте |
