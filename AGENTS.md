# AGENTS.md — правила для ИИ-агентов в репозитории «Партнер»

Этот файл читается агентом первым, до любых других инструкций. Правила обязательны.

## 1. Порядок чтения перед любой задачей

1. `docs/01-product/vision.md` — что за продукт и для кого.
2. `docs/02-policy/time-accounting.md` — ядро расчета. Менять нельзя без ADR.
3. Задача (issue) и её критерии приемки.
4. `docs/05-process/` (см. также CONTRIBUTING.md) — как работать с ветками и ревью.

## 2. Жесткие запреты

- Не менять формулы расчета, ставки, оценку, пул и вестинг без ADR.
- Не мержить в main и не одобрять собственные PR. Пока сопровождающий
  один, branch protection допускает merge своего PR при зеленом CI и
  0 approvals (временное исключение, docs/05-process/github-setup.md);
  при появлении второго ревьюера — обязательный approval, ревьюер ≠ автор.
- Не редактировать принятые начисления; только компенсирующие записи.
- Не писать в репозиторий персональные данные, реквизиты, секреты.
- Не отправлять код клиента и данные во внешние модели без разрешения.
- Не отключать проверки CI ради «зеленого» прогона.

## 3. Учет собственного времени (догфудинг)

Агент, работающий над «Партнером», обязан вести сессию учета:

- старт сессии с привязкой к задаче и человеку-владельцу;
- heartbeat с признаками активности;
- явная маркировка автономных отрезков (человек отсутствует);
- завершение сессии при остановке работы.

Автономное время оплачивается с коэффициентом из политики, а не полностью.
Ответственность за результат несет человек-владелец.

## 4. Маркировка

Коммиты агента: trailer `Co-authored-by: <agent> <agent@…>` и метка `agent`.
В PR — отметка об использовании агента и подтверждение человека-владельца.

## 5. Что агент может сам

Генерировать код и тесты в ветке задачи, обновлять документацию,
запускать линтеры и тесты, готовить черновики отчетов.

## 6. Эскалация

Неоднозначность в правилах расчета → остановиться и спросить человека.
Расхождение с документацией → зафиксировать в issue, не «чинить» правила.

## 7. Проверка перед сдачей задачи

- `pytest` — все 12 приемочных сценариев T-01..T-12 проходят;
- `python tools/policy_lint.py docs/02-policy/policy.example.yaml` — OK;
- измененные цифры сверены с контрольными примерами в документации.
