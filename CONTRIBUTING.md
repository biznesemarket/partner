# Как участвовать в разработке «Партнера»

Перед первой задачей прочитайте `AGENTS.md` — это обязательные правила
работы с репозиторием, в том числе для ИИ-агентов. Процесс веток и ревью
описан в `docs/05-process/development-process.md`.

## 1. Окружение разработчика

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -e ".[dev,server]"
```

Проверка окружения:

```bash
pytest
ruff check .
python tools/policy_lint.py docs/02-policy/policy.example.yaml
```

## 2. Ветки и коммиты

- Базовая ветка — `main`; работа — в ветке `dev/<логин>/<тема>`.
- Коммиты — Conventional Commits: `feat:`, `fix:`, `docs:`, `refactor:`,
  `test:`, `chore:`, `plan(dev):`.
- В PR — ссылка на issue и отметка об использовании ИИ-агента.
- Изменение правил расчета (формулы, ставки, капы, оценка, пул) — только
  вместе с ADR, golden-тестами и документацией в одном PR.
- Коммиты агента маркируются trailer `Co-authored-by: <agent> <agent@…>`.

## 3. Обязательные проверки перед PR

| Проверка | Команда |
|---|---|
| Тесты (T-01…T-12 + сервер, антифрод, дайджесты, юрмодуль) | `pytest` |
| Линтер кода | `ruff check .` |
| Валидация примеров политики | `python tools/policy_lint.py docs/02-policy/policy.example.yaml` и `repo-pack/policy.example.yaml` |
| Миграции | `alembic upgrade head && alembic check` |
| Docs-сайт | `python tools/build_docs_site.py --out docs-site` |

CI выполняет эти же шаги на Linux и Windows. Отключать проверки ради
«зеленого» прогона запрещено.

## 4. Ревью

- `main` защищен: только через PR, обязательный ревьюер ≠ автор, CI зеленый.
- Первый ответ ревьюера — в течение одного рабочего дня.
- Самоприемка запрещена, в том числе через вторую учетную запись.

## 5. Документация

- Все документы — в `docs/`; статус жизненного цикла — в шапке и реестре
  `docs/00-start/docs-plan.md`.
- Числа в примерах должны совпадать с тестами и `policy.example.yaml`.
- При изменении поведения обновляйте CHANGELOG.md в разделе
  `[Незапланировано]`.

## 6. Вопросы и эскалация

Неоднозначность правил расчета — остановиться и спросить человека-владельца
задачи. Расхождение документации и кода — зафиксировать issue, не «чинить»
правила самостоятельно.
